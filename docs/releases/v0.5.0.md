# DataPR v0.5.0

DataPR v0.5.0 begins the v1 stabilization track. It turns the existing analyzer,
Action, schemas, and synthetic validation into a documented public contract and a
reproducible release process. Engineering readiness is now evaluated separately
from production-adoption evidence.

## Highlights

- Declare the CLI, configuration, JSON schemas, finding semantics, Action inputs,
  outputs, and exit codes that form the future v1 compatibility boundary.
- Validate `datapr.example.yml` against a new configuration v1 JSON schema.
- Fail closed on unknown configuration keys, negative policy thresholds, mistyped
  booleans, and invalid profile-directory values.
- Build and inspect both wheel and source distributions on every pull request.
- Install the built wheel and execute CLI smoke tests before release.
- Create immutable GitHub releases automatically from protected `main` tags and
  attach distributions plus GitHub build-provenance attestations.
- Exercise BigQuery schema/lineage, Snowflake SQL-risk policy, and Postgres sampled
  profiling through three explicitly synthetic acceptance environments.

## Install

Install the wheel attached to the GitHub release:

```bash
python -m pip install \
  https://github.com/yvetteYSY/datapr/releases/download/v0.5.0/datapr-0.5.0-py3-none-any.whl
datapr --version
```

Or use the composite Action:

```yaml
- uses: yvetteYSY/datapr@v0.5.0
  with:
    base-manifest: .datapr/base/manifest.json
    head-manifest: target/manifest.json
    config: datapr.yml
```

The movable `v0` tag resolves to the latest backwards-compatible v0 release. Pin
`v0.5.0` or a full commit SHA when reproducibility is more important than receiving
compatible updates.

## Compatibility

`doctor`, `compare`, `measure`, valid configuration version 1, result schema 1,
measurement schema 1, existing finding IDs, and all GitHub Action inputs and
outputs remain compatible with v0.4. Schema-invalid configuration that v0.4
silently coerced or ignored now returns a configuration error. The v0.5 line avoids
further intentional breaking changes while v1.0 is prepared. See the
[v1 stability policy](../v1-stability-policy.md).

## Validation

- Python 3.10, 3.11, and 3.12 unit and golden suites
- composite GitHub Action smoke test
- 50-query, five-dialect lineage corpus
- three-environment synthetic functional matrix
- source distribution and wheel metadata checks
- clean wheel installation and CLI execution
- configuration, result, and measurement schema syntax validation
- provenance-attested release artifacts

## Known limitations

- The release is engineering-ready and publicly usable, but not labeled
  production-proven; independent precision and time-to-first-report evidence is
  still being collected.
- Callers generate dbt manifests and any optional paired profile outputs.
- SQL compatibility is fixture-backed rather than exhaustive for a dialect.
- Differential execution remains bounded and local rather than warehouse-native.
- PyPI publication is not yet enabled; GitHub release assets and the GitHub Action
  are the supported v0.5 distribution paths.
