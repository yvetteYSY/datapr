# DataPR v0.1.0

DataPR brings evidence about a data change into the pull request before merge.

## Highlights

- Detect breaking dbt model and column changes.
- Traverse downstream model impact.
- Infer selected column lineage across five fixture-backed SQL dialects.
- Flag removed filters, cross joins, and wildcard projections.
- Compare paired outputs locally with DuckDB for row-count, null-rate, and numeric-distribution changes.
- Emit terminal, versioned JSON, and update-in-place Markdown PR reports.
- Enforce organization-specific merge policies without requiring an LLM or hosted service.

## Install as a GitHub Action

```yaml
- uses: yvetteYSY/datapr@v0
  with:
    base-manifest: .datapr/base/manifest.json
    head-manifest: target/manifest.json
    config: datapr.yml
    github-token: ${{ secrets.GITHUB_TOKEN }}
```

Use `yvetteYSY/datapr@v0.1.0` to pin this exact release or a full commit SHA for maximum supply-chain control.

## Proof

- The [dangerous-change dogfood PR](https://github.com/yvetteYSY/datapr/pull/1) is intentionally blocked with eight findings.
- The exact report is preserved as a [golden fixture](../../examples/shop_analytics/golden/dangerous-change.md).
- Python 3.10, 3.11, and 3.12 plus the composite action are validated in CI.

## Compatibility

The canonical result schema is `1.0`. DataPR itself is pre-1.0; minor releases may evolve command-line and action inputs based on adopter feedback. See the [changelog](../../CHANGELOG.md) and [roadmap](../../ROADMAP.md).

## Known limitations

- DataPR consumes precompiled base and head manifests.
- SQL coverage is fixture-backed rather than exhaustive.
- Profiling uses pre-materialized local outputs and bounded first-row samples.
- Fork workflows with read-only tokens cannot post comments; DataPR emits a warning and continues enforcement.
