# DataPR v0.2.0

DataPR v0.2.0 makes pull-request evidence more precise, reproducible, and measurable while preserving the version 1.0 result schema.

## Highlights

- Suggest unambiguous model renames from identical artifact fingerprints and declared schemas.
- Suggest unambiguous column renames from identical parsed projection expressions and declared types.
- Keep rename findings inferred and non-blocking; removal findings and merge policies remain intact.
- Select bounded profile rows deterministically with versioned MD5/JSON content hashing.
- Configure a reproducible sample seed or select the legacy `first` strategy explicitly.
- Record the sampling strategy, seed, algorithm, shared columns, and single-thread execution in report evidence.
- Reproduce static-analysis benchmarks at 100, 1,000, and 10,000 models.

## Install as a GitHub Action

```yaml
- uses: yvetteYSY/datapr@v0
  with:
    base-manifest: .datapr/base/manifest.json
    head-manifest: target/manifest.json
    config: datapr.yml
    github-token: ${{ secrets.GITHUB_TOKEN }}
```

Use `yvetteYSY/datapr@v0.2.0` to pin this exact release or a full commit SHA for maximum supply-chain control.

## Upgrade notes

The default differential-profiling strategy changes from file-order-dependent first-row sampling to deterministic content-hash sampling. Existing configurations require no change. To preserve v0.1 behavior temporarily:

```yaml
version: 1
execution:
  sample_strategy: first
```

For a different but reproducible content sample, keep `sample_strategy: hash` and set `sample_seed` to an integer. The result schema remains `1.0`; new coverage and evidence fields are additive.

## Proof

- The full suite contains 27 unit, golden, release, determinism, and benchmark-harness tests.
- Python 3.10, 3.11, and 3.12 plus the composite action are validated in CI.
- The checked-in 20-iteration benchmark measured a 2.0613-second p95 for 10,000 models against the under-30-second target.
- The [dangerous-change dogfood PR](https://github.com/yvetteYSY/datapr/pull/1) remains intentionally blocked.

## Known limitations

- DataPR consumes precompiled base and head manifests.
- Rename candidates are high-precision heuristics, not proof that a migration is safe.
- Hash sampling is distributional rather than row-paired; value changes can change sample membership.
- Profiling consumes pre-materialized local outputs rather than a production warehouse.
- SQL dialect coverage remains fixture-backed rather than exhaustive.
- The Python package is not yet published to PyPI.
