# DataPR v0.3.0

DataPR v0.3.0 hardens pull-request analysis against malformed and unexpectedly large inputs while expanding SQL compatibility evidence. The version 1.0 result schema remains compatible; new coverage fields are additive.

## Highlights

- Validate manifest structure and reject oversized bytes, node sets, column sets, and compiled SQL before analysis.
- Preflight Git-revision artifact sizes before loading their contents.
- Bound differential profiling by sample rows, model count, file size, column count, memory, and a single execution thread.
- Fail closed with controlled errors instead of silently treating missing evidence as safety.
- Verify 50 exact projection-lineage cases across BigQuery, Snowflake, Spark, Postgres, and DuckDB.
- Document security boundaries, configuration, residual risks, and the fail-closed architecture decision.

## Install as a GitHub Action

```yaml
- uses: yvetteYSY/datapr@v0
  with:
    base-manifest: .datapr/base/manifest.json
    head-manifest: target/manifest.json
    config: datapr.yml
    github-token: ${{ secrets.GITHUB_TOKEN }}
```

Use `yvetteYSY/datapr@v0.3.0` to pin this exact release or a full commit SHA for maximum supply-chain control.

## Upgrade notes

Existing configurations remain valid. New profiling boundaries have conservative defaults and are recorded in result coverage when profiling runs. Projects with unusually large local artifacts can raise the configurable profiling limits deliberately; fixed manifest limits are available to library callers through `ManifestLimits`.

Inputs that were previously tolerated despite malformed model structures now produce a controlled usage error. This is intentional fail-closed behavior. See the [resource-limit guide](../resource-limits.md) for defaults and residual risks.

## Proof

- The full suite contains 36 unit, golden, release, resource-limit, determinism, and benchmark-harness tests.
- The dialect corpus contains 50/50 parsing successes and 50/50 exact expected lineage mappings.
- Python 3.10, 3.11, and 3.12 plus the composite action are validated on protected-branch CI.
- DataPR's dogfood workflow validates the changed analyzer and Action on pull requests.

## Known limitations

- Resource boundaries reduce risk but do not provide process isolation or a SQL-parser wall-clock timeout.
- Profiling consumes pre-materialized local outputs rather than a production warehouse.
- Dialect fixtures demonstrate curated compatibility, not production precision.
- Independent adopter measurements for precision, incomplete coverage, and time to first report are still required.
- The Python package is not yet published to PyPI.
