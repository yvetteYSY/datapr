# DataPR v1.0.0rc1

DataPR v1.0.0rc1 is the public compatibility candidate for v1. It intentionally
adds no new analyzer surface. Its purpose is to prove that the frozen CLI,
configuration, result, measurement, finding, and GitHub Action contracts can move
from v0.5 to v1 and roll back without changing comparison evidence.

This is a prerelease for compatibility testing, not the stable v1 channel and not
a claim of independent production validation.

## Install the candidate

```bash
python -m pip install \
  https://github.com/yvetteYSY/datapr/releases/download/v1.0.0rc1/datapr-1.0.0rc1-py3-none-any.whl
datapr --version
```

Use the exact Action tag for a non-critical pilot:

```yaml
- uses: yvetteYSY/datapr@v1.0.0rc1
  with:
    base-manifest: .datapr/base/manifest.json
    head-manifest: target/manifest.json
    config: datapr.yml
    enforce: "false"
```

The stable `v0` channel remains on v0.5.0. No movable `v1` tag is created until
v1.0.0 general availability passes the engineering gates.

## Compatibility rehearsal

Protected CI performs this sequence in a clean environment:

1. install the public v0.5.0 wheel with its recorded SHA-256 and generate a
   comparison result;
2. upgrade to the locally built v1.0.0rc1 wheel;
3. require exact equality with the v0.5 comparison result;
4. reinstall the public v0.5.0 wheel; and
5. require the version and comparison result to return to the baseline.

The detailed comparison contract remains schema 1. Measurement schema 1 also
remains stable; only its documented `datapr_version` value changes.
Follow the [public upgrade and rollback guide](../v1-upgrade.md) for a project
rehearsal.

## Candidate validation

- Python 3.10, 3.11, and 3.12 unit and golden suites
- public v1 CLI, Action, schema, and finding contract snapshot
- 50-query five-dialect lineage corpus
- BigQuery, Snowflake, and Postgres synthetic acceptance matrix
- source and wheel build plus metadata inspection
- clean wheel installation and CLI execution
- v0.5 upgrade, candidate comparison equality, and v0.5 rollback
- exact-tag candidate Action pilot and privacy-safe measurement
- provenance-attested release artifacts

## Feedback requested

Candidate testers should focus on installation, CLI/Action compatibility,
configuration rejection behavior, report parsing, and upgrade/rollback. Share only
sanitized reproductions and privacy-reviewed aggregate measurements.

## Known limitations

- PyPI is not a supported distribution path for this candidate.
- Callers generate dbt manifests and optional paired profile outputs.
- SQL dialect evidence is fixture-backed rather than exhaustive.
- Differential execution is bounded and local rather than warehouse-native.
- Production-adoption evidence remains a separate post-release track.
