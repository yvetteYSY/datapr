# DataPR v0.4.0

DataPR v0.4.0 makes real-project validation measurable without adding hosted telemetry or exposing project identifiers. It adds a separate aggregate measurement contract while preserving comparison result schema 1.0.

## Highlights

- Run the same deterministic comparison pipeline through `datapr measure`.
- Record local analysis duration, decision, model counts, finding-category counts, and coverage counts.
- Exclude manifest paths, repository names, model and column names, SQL, finding messages and evidence, profile file names, and raw values from measurement output.
- Validate aggregate output against the versioned `measurement-v1` schema and a synthetic golden example.
- Follow a documented protocol that separates analyzer duration from end-to-end integration time and defines precision denominators.
- Collect optional adopter feedback through privacy-aware issue forms with no upload or telemetry path.
- Guide contributors with structured bug, feature, adopter, and pull-request templates plus bounded good-first issues.

## Install as a GitHub Action

```yaml
- uses: yvetteYSY/datapr@v0
  with:
    base-manifest: .datapr/base/manifest.json
    head-manifest: target/manifest.json
    config: datapr.yml
    github-token: ${{ secrets.GITHUB_TOKEN }}
```

After publication, use `yvetteYSY/datapr@v0.4.0` to pin this exact release or a full commit SHA for maximum supply-chain control.

## Measure locally

```bash
datapr measure \
  --base-manifest .datapr/base/manifest.json \
  --head-manifest target/manifest.json \
  --config datapr.yml \
  --out datapr-measurement.json
```

DataPR does not send this file anywhere. Review it before sharing it voluntarily. The command reports the policy decision but returns success after producing a valid measurement; continue using `datapr compare --enforce` or the GitHub Action for merge enforcement.

## Upgrade notes

Existing `doctor`, `compare`, configuration, Action inputs, and comparison result schema 1.0 remain compatible. `measurement-v1` is a new, separate contract so aggregate adoption data cannot weaken or expand the detailed comparison-result contract accidentally.

The measurement includes `datapr_version`; golden consumers should expect this value to change with each DataPR release. Finding IDs are product-level categories and are included as aggregate keys. Review those keys before sharing measurements if an organization later adds private policy categories.

## Proof

- The full suite contains 42 unit, golden, release, privacy, resource-limit, determinism, and benchmark-harness tests.
- Python 3.10, 3.11, and 3.12 plus the composite Action are validated on protected-branch CI.
- CI executes `doctor`, detailed JSON comparison, aggregate measurement, and syntax checks for both versioned schemas.
- The golden measurement was delivered through external contributor PR [#15](https://github.com/yvetteYSY/datapr/pull/15), exercising the newcomer workflow end to end.
- The intentionally unsafe dogfood PR [#1](https://github.com/yvetteYSY/datapr/pull/1) remains archived with its blocked review and generated report as historical evidence.

## Known limitations

- No production project measurements are bundled; time-to-first-report, incomplete-coverage, and precision targets still require independent adopters.
- `analysis_seconds` excludes initial integration and artifact-generation time; the protocol records end-to-end wall time separately.
- Aggregate output reduces disclosure risk but adopters must still review it before sharing.
- Profiling consumes pre-materialized local outputs rather than a production warehouse.
- The Python package is not yet published to PyPI.
