# Shop Analytics dogfood project

This small dbt-style project gives DataPR a realistic, inspectable adoption path. It contains staging, order, and revenue models plus a tracked compiled artifact and bounded model output.

The `main` branch represents the safe baseline. The dogfood pull request intentionally changes `orders` in ways DataPR should catch:

- changes `customer_id` from `BIGINT` to `VARCHAR`;
- removes a seven-day filter;
- introduces a cross join;
- increases row count and null rate in the paired output.

Run the safe artifact against itself:

```bash
datapr compare \
  --base-manifest examples/shop_analytics/artifacts/manifest.json \
  --head-manifest examples/shop_analytics/artifacts/manifest.json
```

The repository's `DataPR dogfood` workflow extracts the base artifact and model output from the pull request's target commit. It then invokes the local composite action against the proposed files, posts one report comment, and enforces the result.

The first dogfood run is preserved in [`golden/dangerous-change.md`](golden/dangerous-change.md) and remains visible on [pull request #1](https://github.com/yvetteYSY/datapr/pull/1). The pull request is intentionally open with a failing DataPR check; it must not be merged.

The tracked artifact is intentionally small and hand-verifiable. It models the subset of dbt's manifest contract consumed by DataPR; real adopters should supply artifacts generated by their normal dbt compilation workflow.
